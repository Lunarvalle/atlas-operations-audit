# CRM Cleanroom

Find exact email/phone duplicate candidates and flag conflicting identity and contact-permission fields before a merge.

## The job

Dati importati da fonti diverse creano doppioni e identità in conflitto.

## Start with a synthetic example

1. Open the [input example](../examples/crm-cleanroom-input.json). These are invented test records, never customer data.
2. Read the [computed report](../examples/crm-cleanroom-report.json). It was generated by engine 1.0.0 with an explicit evaluation timestamp.
3. For a licensed installation, load the same fields into the browser app or call MCP tool `crm_cleanroom`.

## Required input

- Table a: `record_id, email, phone, name, company, do_not_contact`
- Table b: ``

CSV accepts comma, semicolon or tab separators. Use decimal points; keep currency explicit. Maximum 5,000 rows per table and 2 MB per file (MCP: 2 MB total request). Dates need a timezone. Missing or ambiguous data is rejected instead of silently guessed.

## Output and review

Structured report, row-level findings, priority actions, formula-safe CSV and an input/result fingerprint through MCP. The local browser edition also exports HTML. Inspect review flags before changing your operational system.

## Boundaries

No automatic merging. Shared phone numbers may represent different people; consent is never inferred.
