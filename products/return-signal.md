# Returns and Refunds Audit — SKU and Reason Report

Join returned line items to the matching sales cohort; separate refunds, handling cost and product/reason patterns.

## The job

Il volume dei resi nasconde cause ricorrenti, differenze fra SKU e costi operativi.

## Start with a synthetic example

1. Open the [input example](../examples/return-signal-input.json). These are invented test records, never customer data.
2. Read the [computed report](../examples/return-signal-report.json). It was generated by engine 1.0.0 with an explicit evaluation timestamp.
3. For a licensed installation, load the same fields into the browser app or call MCP tool `return_signal`.

## Required input

- Table a: `line_id, sku, units, unit_price, currency`
- Table b: `return_id, line_id, units, reason, refund_amount, handling_cost`

CSV accepts comma, semicolon or tab separators. Use decimal points; keep currency explicit. Maximum 5,000 rows per table and 2 MB per file (MCP: 2 MB total request). Dates need a timezone. Missing or ambiguous data is rejected instead of silently guessed.

## Output and review

Structured report, row-level findings, priority actions, formula-safe CSV and an input/result fingerprint through MCP. The local browser edition also exports HTML. Inspect review flags before changing your operational system.

## Boundaries

Requires actual return records. A refund or order edit is not proof that a product came back.
