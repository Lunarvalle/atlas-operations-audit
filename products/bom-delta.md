# BOM Delta

Compare two flat BOM revisions, separating quantity/cost changes from part, unit and currency conflicts.

## The job

Revisioni, quantità, unità e codici produttore cambiano fra engineering e procurement.

## Start with a synthetic example

1. Open the [input example](../examples/bom-delta-input.json). These are invented test records, never customer data.
2. Read the [computed report](../examples/bom-delta-report.json). It was generated by engine 1.0.0 with an explicit evaluation timestamp.
3. For a licensed installation, load the same fields into the browser app or call MCP tool `bom_delta`.

## Required input

- Table a: `part_id, quantity, unit, manufacturer_part, revision, unit_cost, currency`
- Table b: `part_id, quantity, unit, manufacturer_part, revision, unit_cost, currency`

CSV accepts comma, semicolon or tab separators. Use decimal points; keep currency explicit. Maximum 5,000 rows per table and 2 MB per file (MCP: 2 MB total request). Dates need a timezone. Missing or ambiguous data is rejected instead of silently guessed.

## Output and review

Structured report, row-level findings, priority actions, formula-safe CSV and an input/result fingerprint through MCP. The local browser edition also exports HTML. Inspect review flags before changing your operational system.

## Boundaries

No nested BOM explosion, component equivalence or manufacturing approval.
